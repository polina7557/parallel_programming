# Лабораторная работа №1. Перемножение квадратных матриц
## 1. Формулировка задания
Цель работы: написать программу на языке C++ для перемножения двух квадратных матриц.
Исходные данные: файлы, содержащие значения двух исходных матриц.
Выходные данные: файл со значениями результирующей матрицы, время выполнения, объем задачи.
Реализовать автоматизированная верификация результатов вычислений с помощью сторонней программы NumPy.
Определить зависимости времени выполнения от объема задачи.

## 2. Программная реализация
В задаче присутствует кубическая сложность - O(N³). N - размер матрицы.
Был написан скрипт на Python (`generate.py`) дл генерации файлов с матрицами
Перемножение матриц реализовано с помощью стандартного алгоритма, использующего три вложенных цикла.

**Ключевой фрагмент кода - умножение:**
```cpp
for (int i = 0; i < size; i++)
{
    for (int j = 0; j < size; j++)
    {
        for (int k = 0; k < size; k++)
        {
            C[i][j] += A[i][k] * B[k][j];
            operations++;
        }
    }
}
```

## 3. Верификация результатов
Для подтверждения корректности работы программы была проведена автоматизированная проверка. Написан скрипт на Python (`verify.py`), который использует библиотеку `numpy` и её функцию `np.dot()` для вычисления эталонного результата.
Скрипт считывает входные матрицы и результат работы C++ программы, затем сравнивает их.

Результат проверки: `Верно. Результаты одинаковые`.

## 4. Экспериментальные данные и графическое представление
Для анализа производительности программа была запущена на матрицах трёх различных размеров. Время выполнения фиксировалось в микросекундах с помощью библиотеки `<chrono>`, а объём работы (количество операций умножения) подсчитывался с помощью счётчика внутри цикла программы и выводился отдельно.

| Размер матрицы (N) | Объём работы (операций) | Время выполнения (мкс) |
|:---:|:---:|:---:|
| 50 | 125 000 | 2 506 |
| 100 | 1 000 000 | 19 005 |
| 200 | 8 000 000 | 173 817 |

## 5. Выводы
1. **Корректность алгоритма подтверждена.** Автоматизированная проверка с помощью Python-скрипта и библиотеки NumPy показала полное совпадение результатов работы программы с эталонным вычислением через `np.dot()`.
2. **Экспериментально подтверждена кубическая сложность O(N³).** При увеличении размера матрицы в 4 раза (с 50 до 200), объём работы возрос с 125 000 до 8 000 000 операций (ровно в 64 раза), а время выполнения увеличилось с 2 506 мкс до 173 817 мкс (примерно в 69 раз). Теоретические ожидания полностью совпали с практическими результатами.
3. **Последовательный алгоритм имеет ограничения производительности.** Уже на матрице 200×200 время выполнения составляет заметные доли секунды. Для матриц размером 1000×1000 и более такой подход будет работать неприемлемо долго, что обосновывает необходимость использования параллельных вычислений (OpenMP, MPI, CUDA) в следующих лабораторных работах.
